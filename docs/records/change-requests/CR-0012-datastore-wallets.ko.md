# 세션 락 아래 DataStore 에 준법 코인 보관

> 본 문서는 CR-0012 영문 정본의 번역본이다. 내용이 상충하는 경우 영문 정본이 우선한다.

## 1. 요약

준법 코인이 서버보다 오래 남는다. 지갑은 DataStore 에 보관하며, 한 번에 한 서버만 이를 쓸 수 있다.
Application 계층의 판단은 하나도 바뀌지 않는다. `ICoinWalletRepository` 의 두 번째 구현이 첫 번째 구현의 자리를 대신한다.

## 2. 배경

CR-0011 이후, 서버를 떠난 플레이어의 코인은 그 서버가 꺼질 때까지만 남는다.

DataStore 는 코인을 영구히 보관하지만, 두 서버가 같은 지갑을 동시에 쥘 수 있다. 빠르게 다시 접속한 플레이어는 옛 서버가 아직 지갑을 저장하는 동안 새 서버에서 그 지갑을 불러올 수 있다.
그러면 나중의 저장이 이기고, 그 사이에 번 코인은 사라진다.
일반적인 해결책은 기록 자체에 쓰는 세션 락이다. 서버는 지갑을 불러올 때 락을 얻고, 저장할 때마다 갱신하며, 플레이어가 떠나면 놓는다.

## 3. 범위

- 플레이어마다 기록 하나에 지갑을 보관하고, 오직 `UpdateAsync` 로만 읽고 쓰는 `DataStoreCoinWalletRepository`
  - 서버는 지갑을 불러올 때 락을 얻는다. 다른 서버가 쥔 락은 기다리고, heartbeat 가 멈춘 락은 넘겨받는다.
  - 저장은 heartbeat 를 갱신한다. 락이 다른 서버로 넘어간 것을 발견한 저장은 아무것도 쓰지 않고 지갑을 잃었다고 알린다.
  - 모든 요청은 예산을 기다리며, 실패한 요청은 지수 백오프로 재시도한다.
  - 더 새로운 스키마로 쓰인 기록은 덮어쓰지 않고 거부한다.
- 위의 모든 숫자를 담는 `DataStoreConstants`
- `ICoinWalletRepository.Save` 는 지갑을 아직 쥐고 있는지 알리며, `IPlayerSessionSource` 는 플레이어의 연결을 끊을 수 있다.
- `CoinSessionService`
  - `CoinSessionConstants` 에 둔 일정한 간격으로 모든 지갑을 저장한다.
  - 지갑을 불러올 수 없거나 지갑을 잃은 플레이어의 연결을 끊는다.
  - 멈출 때는 남은 지갑을 병렬로 놓아 주고, 이미 진행 중인 해제를 기다린다.
- 서버 조립 지점은 게시된 플레이스에서는 지갑을 DataStore 에 두고, DataStore 에 닿을 수 없는 한 번도 게시되지 않은 플레이스에서는 메모리에 둔다.

바뀌는 통제 문서는 없다.

## 4. 영향도 평가

| 영역 | 영향 |
|---|---|
| 플레이어 | 서버가 꺼져도 코인이 남는다. 다른 서버가 아직 지갑을 쥐고 있으면 플레이어는 몇 초 기다리며, 그래도 놓이지 않으면 다시 접속해 달라는 안내를 받는다. |
| 데이터 | 플레이어마다 기록 하나. 스키마 버전, 잔액, 락을 담는다. |
| DataStore 예산 | 플레이어가 들어올 때 요청 하나, 자동 저장마다 플레이어당 하나, 나갈 때 하나 |
| 시험 | 실제 DataStore 에는 Studio 의 API 서비스 접근을 허용한 게시된 플레이스가 필요하다. 락은 가짜 DataStore 로 검증한다. |
| 문서 분량 | 그대로이다. |

## 5. 원복 계획

본 변경의 머지 커밋을 되돌린다.
DataStore 에 저장된 지갑은 읽히지 않은 채 남고, 코인은 다시 서버가 살아 있는 동안만 남는다.
