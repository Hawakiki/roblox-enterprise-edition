# 계약 메서드마다 래퍼로 선언

> 본 문서는 CR-0023 영문 정본의 번역본이다. 내용이 상충하는 경우 영문 정본이 우선한다.

## 1. 요약

로블록스 코드의 모든 클래스는 구현하는 메서드를 `_implements` 라는 테이블에 선언하며, 그 항목들은 클래스의 메서드를 가리킨다(ADR-0001).
새 타입 솔버는 그런 테이블에 대해 메서드가 있는지만 검사하고 그 이상은 검사하지 않는다. 회사가 아직 옛 솔버로도 코드를 검사하는 이유는 이것 하나이다.
본 변경 요청은 각 항목을 계약의 시그니처로 쓴, 클래스의 메서드를 부르는 함수로 바꾼다. 그러면 두 솔버 모두 계약에서 어긋난 메서드를 래퍼 안의 호출 지점에서 보고한다.
checkpatch 규칙 두 개가 이 형태를 지키고, 생성자 밖에 있는 `any` 캐스트 네 개는 캐스트 없이 다시 쓴다.

본 요청은 회사를 새 솔버 하나로 옮기는 두 요청 중 첫 번째이다. 두 번째 요청은 로블록스 Studio 에서 새 솔버를 켜고 옛 솔버를 없애며, 승인된 문서의 의무를 없애므로 그 릴리스는 2.0.0 이 된다(EE-STD-0008 §4.2).

## 2. 배경

2026-10-31 에 에이전트 세 명이 옛 솔버를 없앨 수 있는지 정하려고 모였다. 한 명은 찬성, 한 명은 반대 입장에서 논하였고, 감사실이 증거를 보관하였다.
`src/` 의 사본에서 `_implements` 의 래퍼는 잘못된 타입의 반환과 빠진 인자에 대해 두 솔버에서 같은 오류를 냈고, 지금 그대로의 클래스에는 아무 오류도 내지 않았다.
구현 여부를 선언하는 `type function` 도 검토하였으나, ADR-0001 이 기록한 이유로 채택하지 않았다.
기록상 결재권자는 두 솔버 모두 모든 메서드를 시그니처로 검사하게 된 뒤에 새 솔버 하나만 남기기로 결정하였다.

본 요청 시점에 `src/` 에는 `_implements` 테이블 열다섯 개와 `any` 캐스트 열일곱 개가 있다.
그중 열세 개는 ADR-0001 이 정한 대로 생성자가 인스턴스를 계약으로 반환하는 자리에 있다.
나머지 네 개는 그렇지 않다. 속성을 읽는 `PolicyAcknowledgementComponent` 에 두 개, `Instance.new` 에 클래스 이름을 넘기는 `RobloxInstanceFactory` 에 한 개, 서비스를 해제하는 `ServiceProvider` 에 한 개이다. 넷 모두 캐스트 없이 쓸 수 있고, 두 솔버 모두 이를 받아들인다.

승인된 결정은 바꾸려고 고치지 않는다(EE-TPL-0004 §1). 래퍼는 ADR-0001 이 계약을 선언하는 방식과, 두 솔버를 유지하는 이유를 바꾸므로, 새 기록이 ADR-0001 을 대체한다.

## 3. 범위

- `src/` 의 모든 `_implements` 테이블: 각 항목을 계약의 시그니처로 쓴, 클래스의 메서드를 부르는 함수로 바꾼다.
- 생성자 밖의 `any` 캐스트 네 개를 캐스트 없이 다시 쓴다.
- 규칙 두 개를 가진 로블록스 코드 검사 `scripts/lib/Contracts.luau` 와 테스트: 함수가 아닌 `_implements` 항목(`IMPLEMENTS_NOT_WRAPPED`), 그리고 `return setmetatable(<state>, <class>) :: any` 밖의 `any` 캐스트(`CAST_THROUGH_ANY`).
- 다음 MINOR 버전으로 `In Review` 개정하는 EE-STD-0006: §6 에 래퍼와 캐스트의 유일한 자리를 정하고, 부속서 A 에 두 규칙을 올린다.
- ADR-0001 의 캐스트를 다시 밝히고 래퍼를 더하는 새 아키텍처 결정 기록. 새 기록이 수락되면 ADR-0001 은 `Superseded` 가 된다.
- 새 기록을 따르도록 바꾼 CR-0020 의 적합성 테스트: 래퍼로 감싼 메서드가 어긋나면 두 솔버가 모두 보고하고, 어긋난 메서드를 가리키기만 하는 항목은 여전히 새 솔버가 보고하지 않는다. 래퍼를 요구하는 이유가 이것이다.
- ADR-0001 을 인용하는 `AGENTS.md` 의 자리.

두 번째 요청으로 미루는 것: 로블록스 Studio 에서 새 솔버를 켜는 설정, 옛 솔버 제거, EE-STD-0001 §4.

## 4. 영향도 평가

| 영역 | 영향 |
|---|---|
| 로블록스 코드 | 테이블 열다섯 개와 캐스트 네 개를 다시 쓴다. `_implements` 테이블을 부르는 곳은 없으므로 동작은 바뀌지 않는다. |
| 타입 검사 | 두 솔버 모두 매개변수, 인자, 반환이 계약에서 어긋난 메서드를 보고한다. |
| 릴리스 | 의무를 더하고 없애거나 바꾸는 것은 없으므로 MINOR 릴리스이다(EE-STD-0008 §4.3). |
| 문서 분량 | 표준 하나 개정, 결정 기록 하나 추가, 하나 대체 |

## 5. 원복 계획

본 변경의 머지 커밋을 되돌린다. `_implements` 의 맨 참조 항목과 캐스트 네 개가 돌아오고, ADR-0001 이 다시 수락 상태가 된다.
