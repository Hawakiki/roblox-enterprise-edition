# EnterpriseEdition 1.0.0 릴리스

> 본 문서는 CR-0014 영문 정본의 번역본이다. 내용이 상충하는 경우 영문 정본이 우선한다.

## 1. 요약

본 변경 요청은 회사의 첫 버전을 릴리스한다. 창립 이후 `develop` 에 승인되어 들어간 모든 것을 `main` 에 머지하고 `v1.0.0` 태그를 붙인다.
릴리스에 앞서 README 에 기록상 결재권자가 쓴 소개문과 한국어판을 더한다.

## 2. 배경

열세 건의 변경 요청이 `develop` 에 승인되어 들어가는 동안, `main` 은 회사 창립 이후 첫 커밋만을 담고 있었다.
릴리스도 다른 변경과 같은 변경이며, 머지 커밋을 포함한 모든 커밋은 자신이 시행하는 변경 요청을 인용한다(EE-POL-0004 §6). 따라서 릴리스에도 자신의 요청이 있다.

기록상 결재권자가 소개문을 한국어로 쓰고, 이를 영어로 옮겨 `README.md` 에 둔다.

## 3. 범위

- `develop` 에서 만든 `release/1.0.0`(EE-POL-0004 §5)
- `README.ko.md`: 기록상 결재권자의 소개문을 포함한 한국어 README
- `README.md`: 영어로 옮긴 소개문, 그리고 두 판 사이의 링크
- 승인 후
  - `release/1.0.0` 을 `--no-ff` 로 `main` 에 머지하고, 그 머지 커밋에 `v1.0.0` 태그를 붙인다.
  - `release/1.0.0` 을 다시 `develop` 에 머지한다.
- 원격 저장소로의 push 는 기록상 결재권자에게 맡긴다.

바뀌는 통제 문서는 없다.

## 4. 영향도 평가

| 영역 | 영향 |
|---|---|
| `main` | 머지 커밋 하나를 거쳐 첫 커밋에서 첫 릴리스로 옮겨 간다. |
| 독자 | 두 언어 중 어느 쪽으로든 README 를 읽을 수 있다. |
| 문서 분량 | 루트의 Markdown 파일 하나. 통제 문서는 없다. |

## 5. 원복 계획

태그 `v1.0.0` 을 지우고, `main` 과 `develop` 의 머지 커밋을 되돌린다.
`main` 은 회사의 역사 내내 그랬듯이 다시 첫 커밋만을 담게 된다.
