# 새 타입 솔버 하나로 검사

> 본 문서는 CR-0025 영문 정본의 번역본이다. 내용이 상충하는 경우 영문 정본이 우선한다.

## 1. 요약

로블록스 Studio 는 새 Luau 타입 솔버로 스크립트를 검사하며, CR-0023 이후 새 솔버는 계약의 모든 메서드를 시그니처에 맞춰 검사한다.
본 변경 요청은 Studio 처럼 새 솔버 하나로 코드를 검사하고, 플레이스에도 그 솔버를 지정한다.
옛 솔버가 없어지면 생성자는 인스턴스를 계약으로 반환하려고 `any` 로 캐스트할 필요가 없으므로, 캐스트를 없앤다. 캐스트는 계약의 메서드가 빠진 클래스를 가렸는데, 이제 새 솔버가 생성자에서 이를 보고한다.
새 솔버는 제네릭 함수 본문에서 타입 매개변수가 얽힌 부분을 검사하지 않으며, 함수 일곱 개에서 생기는 이 손실을 받아들인다.
이 변경을 담는 릴리스는 승인된 문서의 의무를 없애므로 2.0.0 이 된다. 본 요청은 릴리스 워크플로가 1.2.0 을 어떻게 배포했는지도 기록한다.

## 2. 배경

EE-STD-0001 §4 는 모든 Luau 파일을 두 솔버로 검사하게 한다. ADR-0001 이 옛 솔버를 남긴 것은 `_implements` 의 메서드를 계약에 대조하는 것이 옛 솔버뿐이었기 때문이다. CR-0023 이 그 메서드들을 래퍼로 감싸, 이제 두 솔버가 모두 이를 대조한다(ADR-0002).
저장소의 편집기 설정은 이미 luau-lsp 를 새 솔버 하나로 돌린다.

2026-11-01 에 luau-lsp 1.69.0 에서, 옛 솔버가 보고하고 새 솔버가 보고하지 않는 실수는 한 종류였다. 제네릭 함수 본문 안에서 그 타입 매개변수가 얽힌 실수이다.
그런 실수 다섯 가지를 옛 솔버는 모두, 새 솔버는 하나도 보고하지 않았다. 같은 본문에서 매개변수와 무관한 실수, 그리고 제네릭이 아닌 함수의 같은 실수는 두 솔버가 모두 보고하였다.
`src/` 에는 제네릭 함수가 일곱 개 있다. `ServiceToken.new`, `ServiceCollection.AddSingleton` 과 `AddTransient`, `ServiceProvider.GetRequiredService`, `ResourceScope.Adopt` 와 `Using`, `ComponentScope.Adopt` 이다.
기록상 결재권자는 계약의 시그니처를 먼저 검사하게 한다는 조건으로 2026-10-31 에 이 손실을 받아들였고, CR-0023 이 그 조건을 채웠다.

같은 날 push 하지 않는 clone 에서 `src/` 생성자의 `any` 캐스트 열세 개를 없앴다.
새 솔버는 오류를 하나도 보고하지 않았고 옛 솔버는 스물일곱 건을 보고하였으며, 모든 테스트가 통과하였다.
메서드 `Release` 를 `Release2` 로 바꾸고 `_implements` 의 래퍼가 `Release2` 를 부르게 한 클래스는, 생성자가 인스턴스를 캐스트하는 동안 새 솔버에서 오류가 나지 않았고, `Release` 를 처음 부르는 순간 실패했을 것이다. 캐스트를 없애자 새 솔버가 생성자를 보고하였다.

CR-0024 는 1.2.0 을 어떻게 배포했는지의 기록을 다음 요청에 맡겼다.
릴리스 워크플로는 `v1.2.0` 에 대해 run 41261633129 로 돌았다. 달력이 허용하였고, 검사와 빌드와 노트가 통과하였다.
기록상 결재권자가 GitHub 의 검토 창으로 `production` 환경의 배포를 승인하였으며, 이번에는 창이 응답하였다. 배포 7467046918 은 2026-11-01T01:34:54Z 에 만들어졌다.
`v1.2.0` 의 GitHub 릴리스는 2026-11-01T01:36:36Z 에 최신 릴리스로 게시되었고, CR-0018 부터 CR-0024 까지의 노트와, 예행연습이 빌드한 것과 같은 크기인 54824 바이트의 플레이스를 담았다.
`main` 과 `develop` 에 대해 돈 검사도 통과하였다.

## 3. 범위

- `tools/check.sh` 와 `tools/check.ps1`: 각 대상을 새 솔버 하나로 분석한다.
- `default.project.json`: `Workspace.UseNewLuauTypeSolver` 를 `Enabled` 로 두어, 빌드하거나 서빙한 플레이스가 검사에 쓰는 솔버를 갖게 한다.
- `src/` 의 생성자 열세 개: 캐스트 없이 인스턴스를 계약으로 반환한다. `CAST_THROUGH_ANY` 는 `src/` 의 모든 `any` 캐스트를 보고하며, 테스트를 포함한다.
- 2.0.0 으로 `In Review` 개정하는 EE-STD-0001: §4 는 모든 Luau 파일을 새 솔버 하나로 검사하게 한다. 그 하위 문서인 EE-STD-0002, EE-STD-0003, EE-STD-0005, EE-STD-0006 을 이에 맞춰 재검토한다.
- 2.0.0 으로 `In Review` 개정하는 EE-STD-0006: §6 은 생성자가 캐스트 없이 인스턴스를 반환하게 하고, 래퍼는 유지한다.
- 이 결정과 그것이 받아들이는 손실을 기록하고 ADR-0002 를 대체하는 새 아키텍처 결정 기록. 새 기록이 수락되면 ADR-0002 는 `Superseded` 가 된다.
- 새 기록을 따르도록 바꾼 CR-0020 의 적합도 테스트. 옛 솔버는 예제가 담아야 할 실수를 담고 있음을 증언하는 데에만 계속 쓴다.
- ADR-0002 를 인용하거나 파일이 두 솔버로 검사된다고 말하는 `AGENTS.md` 의 자리
- 사람이 로블록스 Studio 에서 플레이스를 열어, 새 솔버를 쓰는지, 코드의 스크립트 분석이 깨끗한지, 플레이 테스트에서 패널이 여전히 준법 코인을 주는지 확인한다.

릴리스 2.0.0 자체는 별도의 요청에 맡긴다.

## 4. 영향도 평가

| 영역 | 영향 |
|---|---|
| 로블록스 코드 | 생성자 열세 개가 캐스트를 잃는다. 동작은 바뀌지 않는다. |
| 타입 검사 | Studio 처럼 솔버 하나이다. 계약의 메서드가 빠진 클래스의 생성자를 보고한다. 제네릭 함수 일곱 개의 본문에서 타입 매개변수가 얽힌 실수는 보고하지 않는다. |
| 검사 시간 | 각 대상을 두 번이 아니라 한 번 분석한다. |
| 릴리스 | 승인된 문서의 의무를 하나 없애므로 MAJOR 릴리스, 2.0.0 이다(EE-STD-0008 §4.2). |
| 문서 분량 | 표준 둘을 MAJOR 버전으로 개정, 셋을 재검토, 결정 기록 하나 추가, 하나 대체 |

## 5. 원복 계획

본 변경의 머지 커밋을 되돌린다. 옛 솔버가 `tools/check` 에, 캐스트가 생성자에 돌아오고, ADR-0002 가 다시 수락 상태가 된다.
