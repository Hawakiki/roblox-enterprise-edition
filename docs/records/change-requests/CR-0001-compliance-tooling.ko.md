# 변경 요청 제도 및 규정 준수 도구 도입

> 본 문서는 CR-0001 영문 정본의 번역본이다. 내용이 상충하는 경우 영문 정본이 우선한다.

## 1. 요약

본 변경 요청은 변경 요청 제도의 도입을 요청한다.
아울러 이를 강제할 도구의 도입을 함께 요청하여, 저장소의 규칙이 기억이 아닌 기계에 의해 지켜지도록 한다.

## 2. 배경

EnterpriseEdition 에는 변경을 승인하는 절차가 없다.
여기에는 그러한 절차를 도입하는 변경도 포함된다.
이 교착 상태를 해소하기 위해 본 요청을 먼저 제출하고, 절차가 마련된 뒤 소급하여 승인한다.

## 3. 범위

- 모든 문서에 대한 기계 판독형 frontmatter 스키마
- `scripts/checkpatch.luau`: 파일 위생, 문서 통제, 커밋 메시지 검사
- `scripts/gen_registry.luau`: frontmatter 로부터 생성되는 문서 대장
- `.githooks/commit-msg`: 규정에 맞지 않는 커밋 메시지를 원천 차단
- `tools/check.sh`, `tools/check.ps1`: 모든 검사의 단일 진입점

## 4. 영향도 평가

| 영역 | 영향 |
|---|---|
| 출력 전달 | 없음. 아직 아무것도 전달하지 않는다. |
| 개발 생산성 | 감소 예상. 의도된 결과이다. |
| 문서 분량 | 대폭 증가 예상. 이 또한 의도된 결과이다. |
| 구성원의 기억력 | 더 이상 의존하지 않는다. |

## 5. 원복 계획

본 변경의 머지 커밋을 되돌린다.
단, 되돌리는 작업 자체에도 변경 요청이 필요하며, 변경 요청을 제출하는 절차는 되돌리는 순간 함께 사라진다.
