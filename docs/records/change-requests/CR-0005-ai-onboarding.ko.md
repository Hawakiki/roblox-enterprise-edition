# AI 인력 온보딩

> 본 문서는 CR-0005 영문 정본의 번역본이다. 내용이 상충하는 경우 영문 정본이 우선한다.

## 1. 요약

저장소의 작업은 대부분 AI 에이전트가 하며, 에이전트는 매 세션을 이전 세션의 기억 없이 시작한다.
본 변경 요청은 그들에게 입구를 마련한다. 모든 에이전트가 가장 먼저 읽는 짧은 파일, 절대 해서는 안 되는 행동을 막는 설정, 그리고 회사 안에서 그들의 위치를 정하는 정책이다.

## 2. 배경

회사의 문서는 25종이며 앞으로 더 늘어난다.
작업마다 문서를 모두 읽는 에이전트는 다른 일을 하지 못하고, 하나도 읽지 않는 에이전트는 첫 커밋에서 규칙을 어긴다.
따라서 입구는 규칙을 다시 적지 않고 길을 안내한다. 지금 하려는 작업을 어느 문서가 다스리는지 알려 주고, 규칙 자체는 문서와 checkpatch 에 맡긴다.

에이전트에게 주는 지시는 맥락일 뿐 강제가 아니다.
그러므로 결재와 머지처럼 사람 없이 일어나서는 안 되는 행동은 문장으로 금지하는 데 그치지 않고, 도구 설정에서도 막는다.

## 3. 범위

- AI 인력 운용 정책: 에이전트의 지위, 벤더 중립, 입구 파일, 안전장치
- 외부 데이터 및 AI 학습 정책: 저장소에 들어올 수 있는 것과, 저장소에서 나가는 것에 대한 회사의 입장
- 그 사이에 오는 정책 2종의 번호를 `Draft` 상태의 자리 표시 문서로 확보
- 모든 에이전트가 공유하는 입구인 `AGENTS.md`, 그리고 이를 불러오고 Claude Code 전용 사항을 더하는 `CLAUDE.md`
- 각 도구에 안전장치를 적용하는 `.claude/settings.json` 과 `.codex/config.toml`
- 신규 규칙 3개: 입구 파일은 실재하는 문서만 인용하고, `CLAUDE.md` 는 `AGENTS.md` 를 불러오며, 입구는 짧게 유지한다.

### 번호 관련 비고

이번 단계의 계획에서는 본 요청을 여섯 번째라 불렀다.
변경 요청은 순서대로 번호를 매기므로(EE-POL-0001 §5) 본 요청이 다섯 번째가 되고, 루트 파일에 대한 요청이 여섯 번째가 된다.

## 4. 영향도 평가

| 영역 | 영향 |
|---|---|
| 출력 전달 | 없음. |
| AI 에이전트 | 첫 순간부터 생산적이며, 말로는 넘어설 수 없는 한계 안에서 일한다. |
| 머지 | 이제 모든 머지는 도구 자체에서 먼저 사람에게 묻는다. |
| 문서 분량 | 문서 4종이 두 언어로, 입구 파일이 2개 늘어난다. |
