# ADR-0001 이 기대는 사실을 검사

> 본 문서는 CR-0020 영문 정본의 번역본이다. 내용이 상충하는 경우 영문 정본이 우선한다.

## 1. 요약

본 변경 요청은 ADR-0001 의 적합도 테스트를 추가한다. 그 결정이 기대는 사실이 바뀌면 테스트가 회사에 알려, 기록을 내버려 두지 않고 다시 검토하게 한다.
아울러 릴리스 워크플로가 1.1.0 을 배포한 경위와, GitHub 의 검토 대화상자가 응답하지 않을 때 기록상 결재권자가 배포를 승인하는 방법을 기록한다.

## 2. 배경

ADR-0001 은 luau-lsp 1.69.0 이 클래스와 그 계약을 다루는 방식에 기대고 있다.
옛 타입 솔버는 `any` 캐스트 없이 계약으로 반환한 클래스 인스턴스를 거부하고, 새 솔버는 받아들인다.
옛 솔버는 계약과 어긋난 메서드를 `_implements` 가 선언하는 곳에서 보고하고, 새 솔버는 아무것도 보고하지 않는다.
새 luau-lsp 가 이 사실 가운데 하나를 바꾸어도, 예컨대 새 솔버가 어긋남을 잡기 시작해도, 회사에 알려 주는 것은 없다.

첫 설계는 테스트의 예제, 곧 일부러 틀리게 쓴 Luau 를 `scripts/tests/solver-fixtures/` 에 두고, 그 폴더를 `tools/check` 의 분석에서 빼는 것이었다.
EE-STD-0001 §4.1 은 모든 `.luau` 파일을 두 타입 솔버에 맞춰 검사하게 하며, 이를 강제하는 것이 `tools/check` 이다.
그 폴더를 빼면 그 파일들에 대해서는 표준이 꺼졌을 것이고, 강제되지 않는 규칙은 권고이다(EE-CHR-0001 제4조).
시행자는 지시를 따르지 않고 멈추어 그 충돌을 보고하였다.
기록상 결재권자는 예제를 테스트 안에 문자열로 두고 테스트가 돌 때 무시되는 `build/` 아래에 쓰기로 정하였다. 그래서 틀린 Luau 는 저장소에 들어오지 않고, `scripts/` 전체가 계속 분석된다.

CR-0017 은 릴리스 워크플로가 1.1.0 을 배포한 경위의 기록을 그다음 요청에 남겼다.
`v1.1.0` 태그는 2026-10-31 에 `main`, `develop` 과 함께 push 되었다.
릴리스 워크플로의 실행 41200439245 는 Calendar 와 Check, build and write the notes 를 차례로 통과하고 `production` 환경에서 기다렸다.
GitHub 이 배포를 검토하는 대화상자가 응답하지 않아, 기록상 결재권자가 `gh api` 로 배포 7458471110 을 승인하였다.
Publish 는 달력을 한 번 더 확인한 뒤, 2026-10-31T12:22:38Z 에 52175 바이트의 `EnterpriseEdition-v1.1.0.rbxl` 과 CR-0015, CR-0016, CR-0017 만 실은 릴리스 노트로 GitHub 릴리스 `v1.1.0` 을 게시하였다.
이것이 최신 릴리스가 되었다.
`main` 과 `develop` 의 검사 실행이 통과하였고, Dependabot 의 첫 실행도 통과하였으며 pull request 는 열지 않았다.

## 3. 범위

- `scripts/tests/AdrFitnessFixtures.luau`: 소스 문자열로 둔 예제 네 개. 메서드가 계약과 어긋난 클래스, 캐스트 없이 계약으로 반환한 클래스, `src/` 가 쓰는 대로의 패턴, 그리고 분석기가 돌았음을 증명하는 뻔한 타입 오류
- `scripts/tests/AdrFitness.spec.luau` 와 `scripts/tests/run.luau` 의 등록: 예제를 `build/solver-fixtures/` 에 쓰고 두 솔버로 분석하며, 결과가 기록이 기대는 것과 다르면 ADR-0001 을 밝히는 메시지로 실패한다.
- `README.md` 와 `README.ko.md`: 검토 대화상자가 응답하지 않을 때 `gh api` 로 배포를 승인하는 방법. 기록상 결재권자가 직접 실행하는 대안으로 적는다.
- `AGENTS.md`: 일부러 틀리게 쓴 Luau 의 지뢰
- 본 요청: 1.1.0 을 배포한 경위의 기록

바뀌는 통제 문서는 없다.

## 4. 영향도 평가

| 영역 | 영향 |
|---|---|
| 아키텍처 | 바뀌는 것은 없다. ADR-0001 이 기대는 사실을 `tools/check` 를 돌릴 때마다 검사한다. |
| 검사 | luau-lsp 분석이 여덟 번 늘어 약 1초가 더 걸린다. git 이 무시하는 `build/` 아래에 파일 네 개를 쓴다. |
| 릴리스 | 바뀌는 것은 없다. 배포를 승인하는 대안을 적어 둔다. |
| 문서 분량 | README 마다 한 줄, 지뢰 하나, 그리고 본 기록 |

## 5. 원복 계획

본 변경의 머지 커밋을 되돌린다.
테스트가 `build/` 아래에 쓴 파일은 누군가 지울 때까지 무시된 채 그 자리에 남는다.
