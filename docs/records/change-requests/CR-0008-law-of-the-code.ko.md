# 로블록스 코드의 규율 확립

> 본 문서는 CR-0008 영문 정본의 번역본이다. 내용이 상충하는 경우 영문 정본이 우선한다.

## 1. 요약

본 변경 요청은 `src/` 아래 로블록스 코드의 규율을 세운다. 쓸 수 없는 지시문과 API, 숫자가 있을 수 있는 유일한 곳, 그리고 코드가 스스로를 문서화하는 방법이다.
확보해 둔 번호에 금지 API 목록과 숫자 리터럴 표준을 작성하고, Luau 코딩 표준의 주석 조항을 개정하고, 세 가지 모두를 checkpatch 로 강제하며, `src/` 아래의 모든 모듈을 이에 맞춘다.

## 2. 배경

회사에는 파일 13개로 된 제품이 있고, 이 제품은 두 줄을 출력한다.
아직은 제품이 그 두 줄을 직접 출력하는 것도, 이름 없는 숫자를 쓰는 것도, 자신의 목적을 밝히지 않는 것도 막는 것이 없다.

기록상 결재권자는 2026-10-30 에 본 요청의 내용을 말로 결정하고 작업을 배정하였다.

| 부분 | 기록상 결재권자의 결정 |
|---|---|
| 지시문 | 허용되는 지시문은 `--!strict` 하나뿐이다. `--!nonstrict`, `--!nocheck`, `--!native`, 수준을 불문한 `--!optimize`, 그리고 `@native` 속성은 예외 없이 금지한다. 회사는 성능보다 절차를 앞에 두기 때문이다. `--!strict` 를 다른 모드와 함께 선언한 파일은 더 이상 통과하지 못한다. |
| API | `print`, `warn`, `Instance.new`, 그리고 `game:GetService` 의 직접 호출을 금지한다. `RobloxOutputLoggerAdapter` 의 `print` 와 `warn` 사용이 첫 번째 인가된 예외이다. 표준은 금지된 API 마다 여전히 허용되는 곳과 그 이유를 밝힌다. |
| 숫자 | `src/` 아래에서는 이름이 `Constants` 로 끝나는 모듈 밖에 숫자 리터럴이 나타나지 아니하며, 0과 1도 마찬가지이다. 상수 모듈은 그 의미를 소유한 계층에 둔다. |
| 문서화 | `src/` 아래의 모든 모듈은 `@class` 를, 계약 모듈이면 `@interface` 를 지닌 Moonwave 문서 주석을 가지며, 그 설명은 영어와 한국어로 쓴다. 모든 공개 함수는 `@within` 과, 해당하는 경우 `@param` 과 `@return` 을 지닌 문서 주석을 영어로 가진다. |

확보해 둔 번호는 각각 별도의 변경 요청으로 작성할 예정이었다.
기록상 결재권자는 세 부분을 하나의 요청으로 배정하였다. 셋이 함께 하나의 코드에 대한 규율이라는 하나의 일관된 변경을 이루기 때문이다(EE-POL-0004 §4).
요청 자체는 말로 승인되지 않았으므로 `Submitted` 로 제출한다(EE-POL-0004 §4).

## 3. 범위

- 확보해 둔 번호에 작성하는 금지 API 목록 EE-STD-0003. 지시문과 속성의 허용 목록, 금지된 API 와 각각이 여전히 허용되는 곳, 그리고 인가된 예외의 대장을 담는다.
  신규 규칙 2개: `PROHIBITED_DIRECTIVE`, `PROHIBITED_API`
- 확보해 둔 번호에 작성하는 숫자 리터럴 표준 EE-STD-0005.
  신규 규칙 1개: `NUMERIC_LITERAL`
- 로블록스 코드의 Moonwave 문서 주석을 다루도록 개정하는 Luau 코딩 표준 EE-STD-0001.
  신규 규칙 4개: `MISSING_MODULE_DOC`, `MISSING_FUNCTION_DOC`, `INCOMPLETE_DOC_COMMENT`, `DOC_COMMENT_LANGUAGE`
- EE-STD-0001 의 새 개정판 기준으로 재검토하고 인용을 갱신하는 EE-STD-0002 와 EE-STD-0006
- checkpatch: 새 규칙이 주변의 주석과 문자열이 아니라 코드를 읽도록 하는 Luau 어휘 분석기
- 동작을 바꾸지 않고 규정에 맞게 다시 쓰는 `src/` 아래의 모든 모듈. Kernel 상수 모듈 2개와 곳곳의 문서 주석
- `AGENTS.md`: 새 표준을 읽을 곳

## 4. 영향도 평가

| 영역 | 영향 |
|---|---|
| 출력 전달 | 그대로이다. 같은 두 줄을, 출력을 인가받은 유일한 모듈이 출력한다. |
| 코드 속 숫자 | `src/` 아래의 모든 숫자가 이름과 자기 모듈을 얻는다. 이제 `1` 을 쓰려면 require 가 필요하다. |
| 개발 생산성 | 이제 모든 함수에는 그것을 설명하는 문단 하나가, 모든 모듈에는 문단 둘이 따라붙는다. 의도된 결과이다. |
| 문서 분량 | 개수는 그대로이다. 확보해 둔 표준 2종을 작성하고 1종을 개정할 뿐, 추가하는 것은 없다. |

## 5. 원복 계획

본 변경의 머지 커밋을 되돌린다.
코드는 다시 마음대로 출력하고, 1부터 센다고 밝히지 않고 세며, 자신의 목적을 혼자 간직하게 된다.
