# 전역 난수 생성기 금지

> 본 문서는 CR-0022 영문 정본의 번역본이다. 내용이 상충하는 경우 영문 정본이 우선한다.

## 1. 요약

회사의 로블록스 코드는 아직 난수를 한 번도 뽑지 않았다. 그러기 전에, 본 변경 요청은 `math.random` 과 `math.randomseed` 를 금지한다. 그 하나뿐인 숨은 생성기는 어떤 코드든 시드를 다시 줄 수 있고, 어떤 테스트도 결과를 고정할 수 없다.
`Random.new` 는 Infrastructure 에서만 허용하여, 우연은 계약을 거쳐서만 나머지 코드에 닿게 한다. 테스트는 그 계약을 전혀 무작위가 아닌 가짜로 바꿀 수 있다.

## 2. 배경

EE-STD-0003 §5 의 금지 API 목록은 이미 컨테이너 밖의 전역 상태인 `_G` 와 `shared`, 그리고 실행하는 기계에 따라 결과가 달라지는 `tick` 을 금지한다.
`math.random` 은 두 결함을 다 가졌다. 생성기는 전역이고 math 라이브러리 속에 숨어 있으며, `math.randomseed` 를 부르는 누구에게나 시드가 바뀌고, 테스트는 그것이 내놓는 값을 고정할 수 없다.
회사는 이미 코드가 시계를 직접 읽지 않고 시각을 주입받게 한다. 정책 확인 보상과 DataStore 지갑이 그렇다. 우연도 그 곁에 둔다.

`src/` 의 어떤 모듈도 두 API 를 부르지 않고 `Random` 을 만들지도 않으므로, 바꿀 것은 없다.
두 API 를 대신할 계약은 우연이 필요한 첫 기능이 선언하며, 그 전에는 만들지 않는다.
EE-STD-0003 §5.4 는 그 표가 표준의 개정으로 늘어난다고 정한다.

## 3. 범위

- 1.1.0 으로 `In Review` 개정하는 EE-STD-0003: `math.random` 과 `math.randomseed` 를 어디서나 금지하는 행, 그리고 `Random.new` 를 Infrastructure 모듈에서만 허용하는 행
- checkpatch 가 보관하는 대장 사본 `scripts/lib/ProhibitedApis.luau`: 두 행, 그리고 API 를 허용할 수 있는 곳으로서의 Infrastructure 모듈. 테스트를 포함한다.

정책, 표준, 절차, 양식, 기록 종류, 문서 규칙은 하나도 추가하지 않는다. 새 행은 `PROHIBITED_API` 가 보고한다.

## 4. 영향도 평가

| 영역 | 영향 |
|---|---|
| 로블록스 코드 | 지금 바뀌는 것은 없다. 우연이 필요한 코드는 계약을 거쳐 받는다. |
| 테스트 | 우연에 따라 달라지는 동작을 가짜 난수원으로 테스트할 수 있다. |
| 문서 분량 | 표준 하나의 두 행 |

## 5. 원복 계획

본 변경의 머지 커밋을 되돌린다. `math.random` 이 다시 허용된다.
