# 회사 공개 준비

> 본 문서는 CR-0013 영문 정본의 번역본이다. 내용이 상충하는 경우 영문 정본이 우선한다.

## 1. 요약

저장소는 지금 모습 그대로 공개한다. 기능은 참조 구현이고 기록은 연혁인, 참조용 회사로서이다.
본 변경 요청은 공개 저장소에 필요하지만 회사에 없던 것을 더한다. 개발 워크플로우를 담은 README, 기여자 안내, 그리고 모든 push 와 pull request 에서 모든 검사를 돌리는 지속적 통합이다.

## 2. 배경

기록상 결재권자는 저장소를 빈 템플릿으로 덜어 내지 않기로 결정하였다.
준법 인센티브 제도는 회사에게, 회사가 풍자하는 작품에서 FizzBuzz 가 맡은 역할과 같다. 구조가 섬기기 위해 존재하는 하찮은 기능이다.
어쨌든 기록은 지울 수 없다. 문서, 코드, `AGENTS.md` 가 기록을 인용하며, checkpatch 는 그 인용을 하나하나 보고할 것이다(`DANGLING_REFERENCE`).
회사는 자기 과거를 잊을 수 없다.

본 요청이 더하는 파일은 어느 것도 통제 문서가 아니며, 거버넌스는 동결된 채로 남는다.

## 3. 범위

- `README.md`: 개발 워크플로우. 소개문은 기록상 결재권자에게 맡긴다.
- `CONTRIBUTING.md`: 사람이 기여하는 방법을, 그것을 다스리는 문서를 거쳐 안내한다.
- `.github/workflows/check.yml`: `main` 이나 `develop` 으로의 모든 push 와 모든 pull request 에서, `rokit.toml` 이 고정한 툴체인을 설치하고 `tools/check.sh` 를 돌리며 첫 커밋 이후의 모든 커밋 메시지를 검사한다.
  - 사용하는 외부 액션은 태그가 아니라 커밋으로 고정한다.
  - 도구를 신뢰하는지 묻지 않고 설치한다. 다른 모든 변경처럼 승인을 받은 워크플로가, 자기 기계에서라면 도구를 신뢰했을 사람을 대신하여 신뢰한다.

## 4. 영향도 평가

| 영역 | 영향 |
|---|---|
| 기여자 | README 는 시작하는 방법을, CONTRIBUTING 은 고용되는 방법을 알려 준다. |
| 검증 | 모든 push 와 pull request 를, 회사의 누구도 손으로 돌리지 않는 기계가 검사한다. |
| 문서 분량 | 루트의 Markdown 파일 두 개. checkpatch 가 이미 입구 파일로 다스린다. 통제 문서는 없다. |

## 5. 원복 계획

본 변경의 머지 커밋을 되돌린다.
저장소는 안내 없이 공개되며, 대부분의 저장소가 그렇게 공개된다.
