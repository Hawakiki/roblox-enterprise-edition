# AI 인력 운용 정책

> 본 문서는 EE-POL-0006 영문 정본의 번역본이다. 내용이 상충하는 경우 영문 정본이 우선한다.

## 1. 목적

본 정책은 회사 안에서 AI 에이전트의 위치, 즉 할 수 있는 일과 절대 할 수 없는 일, 그리고 그들에게 업무를 안내하는 방식을 정한다.

## 2. 적용 범위

본 정책은 벤더와 관계없이 저장소에서 일하는 모든 AI 에이전트와, 그들을 안내하고 제한하는 파일 및 설정에 적용한다.

## 3. 정의

| 용어 | 정의 |
|---|---|
| 에이전트 | 저장소의 무엇이든 읽거나 쓰거나 실행하는 AI 시스템 |
| 입구 파일 | 에이전트와 사람이 가장 먼저 읽는, 저장소 루트의 Markdown 파일 |
| 공용 입구 | 모든 에이전트가 읽는 입구인 `AGENTS.md` |
| 벤더 파일 | `CLAUDE.md`, `.claude/settings.json`, `.codex/config.toml` 처럼 한 벤더의 에이전트만 읽는 파일 |
| 안전장치 | 에이전트가 무엇을 결정하든 그 행동을 막거나 멈추게 하는 도구 설정 |

## 4. 에이전트의 지위

1. 에이전트는 수습 중인 회사 구성원이다. 수습 기간은 끝나지 아니한다.
2. 에이전트는 사람이 지키는 모든 규칙을 지키며, 같은 checkpatch 로 검사받는다.
3. 에이전트는 초안 작성, 구현, 시험, 제안, 변경 요청 제출을 할 수 있다.
4. 에이전트는 무엇도 승인하지 아니한다. 변경 요청도, 문서도, 머지도 마찬가지이다(EE-POL-0004 §4).
   기록상 결재권자가 같은 세션에서 말로 승인한 경우에만 그 승인을 기록한다.
5. 에이전트는 자기 이름으로 서명(sign-off)하지 아니한다.
   에이전트는 자신이 대신하여 일하는 사람을 위해서만, 그 사람의 git 신원과 권한으로 `Signed-off-by` trailer 를 쓰며, 커밋에 대한 책임은 그 사람이 진다(EE-STD-0007 §6).
   에이전트는 `Co-Authored-By` trailer 에 이름을 올린다.

## 5. 벤더 중립

1. `AGENTS.md` 는 모든 에이전트의 단일 입구이다. 어떤 벤더도 다른 벤더가 받지 않는 규칙을 받지 아니한다.
2. 벤더 파일은 공용 입구가 자기 에이전트에게 닿게 하고, 그 도구에만 해당하는 것을 더할 뿐이다. 도구를 다루는 방법은 더할 수 있으나, 에이전트가 할 수 있는 일은 더하지 아니한다.
3. `CLAUDE.md` 는 Claude Code 가 불러오기를 건너뛰는 코드 밖에서, 한 줄을 차지하는 구문으로 `AGENTS.md` 를 불러온다(`MISSING_AGENTS_IMPORT`).

## 6. 입구 파일

1. 입구는 규칙을 다시 적지 않고 길을 안내한다.
   지금 하려는 작업을 어느 문서가 다스리는지 알려 주고, 규칙 자체는 문서와 checkpatch 에 맡긴다.
2. `AGENTS.md` 와 `CLAUDE.md` 는 합쳐서 Claude Code 가 지시문에 권장하는 길이인 200줄 이내로 유지한다(`ONBOARDING_TOO_LONG`).
3. 입구 파일은 실재하는 문서만 인용한다(`DANGLING_ENTRY_REFERENCE`).
4. 에이전트가 저지른 실수 중 어떤 규칙도 잡지 못한 것은, 그 실수의 기록과 함께 입구의 "선배들이 밟은 지뢰"에 추가한다.

## 7. 안전장치

1. 지시는 맥락일 뿐 강제가 아니다.
   사람 없이 일어나서는 안 되는 행동은 도구에서도 막는다.
2. Claude Code 는 `.claude/settings.json` 으로 다음 안전장치를 적용한다.

| 행동 | 설정 |
|---|---|
| `.env` 읽기 | 거부 |
| `git push` | 거부 |
| `git commit --amend`, `git rebase`, `git reset --hard` | 이력 재작성으로 보아 거부(EE-CHR-0001 제7조) |
| `git merge` | 먼저 사람에게 확인 |

3. Codex 는 `.codex/config.toml` 로 이를 적용한다. 쓰기는 저장소 안으로 한정되고, 네트워크는 닫혀 있으며, 에이전트는 샌드박스를 벗어나기 전에 묻는다.
4. 도구가 표현할 수 없는 안전장치는 입구에 적고, 가능한 경우 checkpatch 로 강제한다.
5. 안전장치는 보안 경계가 아니다. 작정한 에이전트는 명령을 바꿔 쓸 수 있다.
   안전장치는 정직한 에이전트가 정직한 실수를 하지 못하게 하기 위해 존재한다.

## 8. 강제 수단

§5 와 §6 은 checkpatch 가, §7 은 각 도구가 강제한다.
부속서 A 는 본 정책을 근거로 하는 규칙을 열거한다.
