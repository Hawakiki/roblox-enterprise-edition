# 변경 관리 정책

> 본 문서는 EE-POL-0004 영문 정본의 번역본이다. 내용이 상충하는 경우 영문 정본이 우선한다.

## 1. 목적

본 정책은 저장소의 모든 것이 바뀌는 방식을 정한다.
본 정책은 헌장의 세 번째 핵심 가치인 "모든 변경에는 요청이 있다"를 시행한다(EE-CHR-0001 제3조).

## 2. 적용 범위

1. 본 정책은 본 정책 자신을 포함하여, 저장소의 모든 파일에 대한 모든 변경에 적용한다.
2. 커밋 `8f2b559` 는 본 정책보다 앞서므로 적용을 면제한다(EE-CHR-0001 제7조).

## 3. 정의

| 용어 | 정의 |
|---|---|
| 변경 | 저장소에 대한 모든 커밋 |
| 변경 요청 | 변경을 요청하는 기록. EE-TPL-0002 양식으로 제출한다. |
| 기능 브랜치 | 변경 요청 하나를 시행하는 브랜치 |
| 기록상 결재권자 | 이사회를 대행하여 결재하는 사람(EE-CHR-0001 제5조) |

## 4. 변경 요청

1. 변경 요청은 변경 작업을 시작하기 전에 제출한다.
2. 변경 요청 하나는 하나의 일관된 변경을 다룬다. 관련 없는 변경은 따로 요청한다.
3. 변경 요청은 해당 종류의 상태를 거친다(EE-POL-0001 §10).

| 상태 | 의미 |
|---|---|
| `Submitted` | 제출되어 결정을 기다리는 중 |
| `Approved` | 작업을 진행할 수 있음 |
| `Rejected` | 작업을 진행할 수 없음 |
| `Implemented` | 변경이 완료되어 머지되었거나 머지 직전임 |
| `Closed` | 더 이상 커밋을 받지 않음 |

4. 결재는 사람인 기록상 결재권자가 한다.
   어떤 에이전트도, 할 수 있든 없든, 변경 요청이나 문서나 머지를 스스로 승인하지 아니한다.

## 5. 브랜치 모델

1. 저장소는 git-flow 를 따른다.

| 브랜치 | 용도 | 분기 원천 | 머지 대상 |
|---|---|---|---|
| `main` | 배포된 상태 | — | — |
| `develop` | 승인된 변경의 통합 | `main` | 배포를 거쳐 `main` |
| `feature/CR-<NNNN>-<slug>` | 변경 요청 하나 | `develop` | `develop` |
| `release/<version>` | 배포 준비 | `develop` | `main` 과 `develop` |
| `hotfix/SEV<1-4>-<slug>` | 배포본의 긴급 수정 | `main` | `main` 과 `develop` |

2. `main` 과 `develop` 은 머지 커밋만 받는다. 누구도 이 두 브랜치에 직접 커밋하지 아니한다.
3. 모든 머지는 `--no-ff` 로 하여, 각 변경이 이력에서 한 단위로 보이게 한다.
4. 브랜치 이름은 EE-STD-0007 을 따른다.

## 6. 커밋

1. 모든 커밋은 자신이 시행하는 변경 요청을 인용하며, EE-STD-0007 을 따른다.
2. 모든 커밋은 저장소를 `tools/check` 를 통과하는 상태로 남긴다.
3. 커밋하기 전에 그 커밋에 올라간 파일을 검토한다(CR-0002).

## 7. 결재와 머지

1. 작업이 끝나면 변경 요청의 시행 기록에 시행 커밋을 적고, 상태를 `Implemented` 로 바꾸며 MINOR 를 올린다.
2. 기록상 결재권자가 결과를 검토하고 머지를 승인한다.
3. 머지 커밋에는 기록상 결재권자를 명시한 `Approved-by` trailer 를 단다.
4. 변경 요청이 바꾼 통제 문서는 같은 검토에서 함께 승인하며, 머지 전에 `In Review` 에서 `Approved` 로 바꾼다(EE-POL-0001 §10).

## 8. 정정 변경

1. 이미 커밋된 실수는 이력을 고쳐 쓰지 않고, 새 변경 요청으로 정정한다(EE-CHR-0001 제7조).
2. 정정 변경 요청에는 CR-0002 처럼 실수의 근본 원인과 시정 조치를 기록한다.

## 9. 긴급 변경

1. 긴급은 면제 사유가 아니다. 더 빨리 제출하는 변경 요청일 뿐이다.
2. 배포본의 긴급 수정은 사고의 심각도를 이름에 넣은 hotfix 브랜치에서 하며, 사고 뒤에는 포스트모템을 연다.

## 10. 강제 수단

본 정책은 EE-STD-0007 을 통해 강제하며, commit-msg 훅이 모든 커밋에 그 규칙을 적용한다.
본 정책 자체를 근거로 하는 checkpatch 규칙은 없다.
