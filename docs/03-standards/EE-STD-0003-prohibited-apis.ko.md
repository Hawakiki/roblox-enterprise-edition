# 금지 API 목록

> 본 문서는 EE-STD-0003 영문 정본의 번역본이다. 내용이 상충하는 경우 영문 정본이 우선한다.

## 1. 목적

본 표준은 어떤 Luau 파일도 선언하지 않는 지시문과, 로블록스 코드가 직접 쓰지 않는 로블록스 및 Luau API 를 열거하고, 각각이 여전히 허용되는 곳과 코드가 대신 쓰는 것을 정한다.

## 2. 적용 범위

1. §4 는 `scripts/` 아래의 도구를 포함하여 저장소의 모든 Luau 파일에 적용한다. §4 는 EE-STD-0001 §3 이 모든 Luau 파일에 요구하는 strict 모드를 지키기 때문이다.
2. §5 와 §6 은 조립 지점을 포함하여 `src/` 아래의 로블록스 코드에 적용한다.

## 3. 정의

| 용어 | 정의 |
|---|---|
| 지시문 | `--!` 로 시작하는 주석. Luau 는 이를 타입 검사기나 컴파일러에 대한 지시로 읽는다. |
| 속성 | `@native` 처럼 함수 앞에 놓이고 `@` 로 시작하는 이름. Luau 는 이를 컴파일러에 대한 지시로 읽는다. |
| 금지 API | §5 에 열거한 전역 이름 또는 전역 이름의 멤버 |
| 인가된 예외 | §6 이 경로를 지정하여 금지 API 의 사용을 허용한 모듈 |
| 조립 지점 | `init.server.luau` 또는 `init.client.luau`(EE-STD-0006 §4) |

## 4. 지시문과 속성

1. 지시문과 속성은 허용 목록으로 관리한다. 목록에 없는 것은 금지된다(`PROHIBITED_DIRECTIVE`).
2. 목록에 있는 지시문은 EE-STD-0001 §3 이 요구하기도 하는 `--!strict` 하나뿐이다. 목록에 있는 속성은 없다.
3. 특히 `--!nonstrict`, `--!nocheck`, `--!native`, 수준을 불문한 `--!optimize`, 그리고 `@native` 속성은 예외 없이 금지한다.
4. `--!strict` 곁에 다른 지시문을 함께 선언한 파일은, 둘 중 어느 쪽이 먼저 오든 다른 지시문 때문에 보고된다.
   `--!strict` 를 선언하는 것만으로는 충분하지 않으며, 그 밖에 아무것도 선언하지 않아야 한다.
5. 그 이유는 섣부른 최적화가 모든 악의 근원이고, 회사는 성능보다 절차를 앞에 두기 때문이다.
   `--!nonstrict` 와 `--!nocheck` 는 편의를 위해 타입 검사기를 포기하는 것이고, `--!native`, `--!optimize`, `@native` 는 속도를 위해 컴파일러를 조정하는 것이다.
   회사는 어느 쪽도 하지 아니한다.
6. 지시문이나 속성에 대해서는 §6 에 따른 예외를 인가하지 아니한다.

## 5. 금지 API

1. 로블록스 코드는 금지 API 를 아래 표가 허용하는 곳에서만 쓰며, 그 밖의 모든 곳에서는 표가 지정한 것을 대신 쓴다(`PROHIBITED_API`).

| API | 여전히 허용되는 곳 | 그곳에서 허용되는 이유 | 대신 쓰는 것 |
|---|---|---|---|
| `print`, `warn` | §6 의 인가된 예외 | 출력 창은 외부 시스템이며, 어댑터 하나가 그 위에 `ILogger` 를 구현한다(EE-STD-0006 §6). | 컨테이너에서 꺼낸 `ILogger` |
| `Instance.new` | 이름이 `Factory` 로 끝나는 Infrastructure 모듈 | 인스턴스는 로블록스의 것이며 로블록스를 아는 것은 Infrastructure 뿐이고(EE-STD-0006 §4), 객체를 만드는 것은 팩토리의 일이다(EE-STD-0002 §3). 호출한 쪽은 받은 것을 `ResourceScope` 에 맡긴다(EE-STD-0006 §8). | Application 이 선언한 계약을 거친 팩토리 |
| `game:GetService`, `game:FindService` | 조립 지점 | 정적 require 경로는 서비스에서 시작하며(EE-STD-0001 §7), 조립 지점은 컨테이너를 require 하기 전까지 서비스를 꺼낼 컨테이너가 없다. 조립 지점은 이미 모든 구현을 알고 있으므로(EE-STD-0006 §4), 모든 서비스를 안다고 해서 더해지는 것은 없다. | 생성자. 조립 지점이 각 모듈에 필요한 서비스를 넘긴다. |
| `wait`, `delay`, `spawn` | 없음 | 폐지됨. task 라이브러리가 이를 대체하며, 이들은 속도가 제한된 스케줄러의 보폭에 맞춰 늦게 재개된다. | `task.wait`, `task.delay`, `task.spawn` |
| `tick` | 없음 | 로블록스가 권하지 않음. 결과가 실행하는 기기의 시계와 시간대에 따라 달라진다. | `os.clock`, `os.time`, `DateTime` |
| `loadstring` | 없음 | 위험함. 타입 검사기도, checkpatch 도, 기록상 결재권자도 보지 못하는 코드를 실행한다. | 정적 경로로 require 한 모듈 |
| `getfenv`, `setfenv` | 없음 | Luau 에서 폐지되었고 위험함. 다른 함수의 환경을 읽고 바꾸어, 타입 검사기와 본 목록으로부터 전역 이름을 가린다. | require 와 매개변수 |
| `_G`, `shared` | 없음 | 위험함. 컨테이너 밖에서 이름으로 찾는 전역 상태를 담으며, 이는 EE-STD-0006 §7 이 금한다. | 토큰으로 꺼낸 서비스 |

2. API 는 이름이 나오는 곳이면 어디서든 쓰인 것으로 본다. 호출, `local log = print` 같은 별칭, 그리고 `game.GetService(game, name)` 처럼 멤버를 거친 경우를 모두 포함한다.
   `wait`, `delay`, `spawn`, `tick` 은 호출될 때만 보고하여, `spawn` 처럼 우연히 같은 이름을 가진 지역 변수는 그대로 둔다.
3. `logger.print` 처럼 다른 값의 필드나 메서드가 API 와 이름이 같은 것은 그 API 가 아니다.
4. 표는 본 표준의 개정으로 늘어난다.
   모든 항목은 API, 그것이 여전히 허용되는 곳과 그 이유, 그리고 대신 쓰는 것을 밝힌다.

## 6. 인가된 예외

1. 인가된 예외는 경로로 지정한 모듈 하나가 대장에 적은 금지 API 를, 대장에 적은 이유로 쓸 수 있게 허용한다.
2. 예외는 본 대장을 개정하는 변경 요청으로 인가하며, 기록상 결재권자가 그 개정을 승인할 때 효력이 생긴다.
3. checkpatch 는 대장의 사본을 `scripts/lib/ProhibitedApis.luau` 에 두며, 같은 변경 요청이 이를 갱신한다.
4. 예외를 쓰는 모듈은 쓰는 곳마다 그 옆에 주석으로 이를 밝힌다.

| 모듈 | API | 이유 | 인가 근거 |
|---|---|---|---|
| `src/Shared/Infrastructure/RobloxOutputLoggerAdapter.luau` | `print`, `warn` | 다른 어떤 API 로도 닿을 수 없는 로블록스 출력 창 위에 `ILogger` 를 구현한다. 첫 번째 인가된 예외이다. | CR-0008 |

## 7. 시행

checkpatch 가 §4 부터 §6 까지를 강제한다.
